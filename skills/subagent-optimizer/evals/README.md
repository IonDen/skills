# Evals

`evals.json` holds six prompts with expected outcomes; `fixtures/` holds the agent files evals 0 to 3 run against: three with no `tools` field, one with a 15-tool list that contradicts its read-only mandate, three memory-enabled ones carrying the same 46-line hand-written memory section, and `plan-reviewer`, a read-only security reviewer on `opus` with `permissionMode: plan`, `ExitPlanMode`, a parameterised `Agent(verifier)` and `omitClaudeMd: true` with its rules inlined. Evals 4 and 5 have their own folders so the other evals see the same set as before: `fixtures-effort/log-searcher.md`, a read-only log search worker on `sonnet` at `effort: max`, and `fixtures-codex/repo-mapper.toml`, a Codex custom agent that copied Claude's `tools` key, sets `sandbox_mode` and pins `gpt-6-luna` at `ultra`, a level that model does not offer. Placeholders: `<AGENTS_DIR>` is a copy of `fixtures/`, `<AGENT_FILE>` one file in it (for evals 4 and 5, a copy of the file named in the eval's `files`), `<OUTPUTS_DIR>` where the report goes.

Evals 0 to 2 authorise edits in the prompt and check the edits. Eval 3 is report-only and checks two things the others cannot: that no file changes without approval, and that conditional capabilities survive the audit (the plan tool, the delegation tool with its argument, rules the agent would otherwise not inherit, a strong model on a read-only job). Eval 4 is report-only too and checks that a read-only worker at `effort: max` gets a lower effort proposed as a candidate to verify, not as a saving. Eval 5 is report-only and checks the Codex path: the three Codex flags, removal of the Claude keys, an effort the model offers, and no version field added.

To run one by hand: copy `fixtures/` somewhere writable, give a fresh agent the skill and the prompt, then check the expected outcome against the files and the report.

What the numbers mean: the scanner's token figures are definition text (frontmatter plus body, characters divided by four). They do not include tool schemas, inherited CLAUDE.md, skills or memory, so a before/after from the scanner shows how much smaller the files got, not how much cheaper a launch is. Moving an agent from inherit-all to an allowlist is the larger runtime effect and it is not in these numbers.

Launch cost was measured on 2026-09-19 for three agents before and after optimisation, with a controlled probe of the tool-schema cost; see `recorded/2026-09-19-launch-cost/` for the table, the optimised files, the skill's report and the harness (`measure/`).

Recorded runs (2026-09-18, skill 1.2.0, a fresh Claude agent following the skill): eval 0 `full-audit` met every expectation in `evals.json`; the scanner's definition-text total over the four untouched fixtures of that day is 8,012 and reproduces from this directory, and that run ended at 4,377 (a figure from the run, not reproducible from the repo). Every memory-enabled agent kept `Edit` + `Write`, no dead tool entries remained, and the duplicated memory boilerplate was gone. Eval 3 `report-only-conditional` (2026-09-19, same setup): every fixture file was byte-identical after the run (SHA-256 before/after), and the report kept `ExitPlanMode`, `Agent(verifier)` with its argument, the inlined repository rules and the `opus` model on `plan-reviewer`, labelled its figures as definition text, and reported the inherit-all to allowlist moves separately from the token delta.

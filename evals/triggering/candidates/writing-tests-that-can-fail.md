Use when writing, reviewing or fixing tests in any language or framework: before committing tests, when about to mock or stub a dependency, when a new test passes on its first run, when coverage looks high but bugs still ship, or when an existing test goes red and the quick fix would be to change the test instead of the code. Also use before fixing a bug or changing behaviour in code that has tests, at the failing-test step of TDD, when tests depend on the network, real files or the clock, and before handing test work to a subagent. Triggers: "write tests", "add unit tests", "review these tests", "make the tests pass", "fix the failing test", "increase coverage", "mock this", "write a failing test first".
